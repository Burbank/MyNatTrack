## (a) Before entering MNPS airspace

The following procedure shall be performed **working in sequence and independently**.

### Step 1 – Dual Listening & Recording (Cannot be delegated)

| Role | Action |
|------|--------|
| **Both PF & PM** | Where practicable, two flight crew members should listen to and record every ATC clearance. |
| **Both** | Both agree that the recording is correct. |
| **Both** | Must include: independent clearance copy, data entry (Coordinates and/or named waypoints), and independent crosschecks to verify that the clearance is correctly programmed. |
| **Note** | These procedures must also be used when enroute changes are entered. |
| **Critical** | This task **cannot be delegated**. Any doubt should be resolved by requesting clarification from ATC. |

```
          ┌─────────────────────────────────────┐
          │  Dual independent listen + record   │
          │  + independent clearance copy       │
          │  + data entry + crosschecks        │
          │  (Cannot be delegated)              │
          └──────────────────┬──────────────────┘
                             │
                             ▼
```

### Step 2 – PM Actions (OFP Note & Route Comparison)

| Role | Action |
|------|--------|
| **PM** | Enter the received clearance as **Note** in the OFP. |
| **PM** | For clearances received by ACARS → make a reference i.a.w. OM-A **8.1.10.2**. |
| **PM** | Check if the cleared route is different from the flight plan route. |

**If cleared route is different:**

1. Revise the waypoint name; **and**
2. Crossload OFP and Notes.

```
          ┌─────────────────────────────────────┐
          │  PM: Enter as Note in OFP           │
          │  (ACARS → ref OM-A 8.1.10.2)        │
          │  Check cleared route vs FPL         │
          └──────────────────┬──────────────────┘
                             │
               ┌─────────────┴─────────────┐
               │                           │
          Different?                   Same
               │                           │
               ▼                           │
     ┌─────────────────────┐               │
     │ (i) Revise WPT name │               │
     │ (ii) Crossload OFP  │               │
     │     and Notes       │               │
     └──────────┬──────────┘               │
                │                          │
                └────────────┬─────────────┘
                             │
                             ▼
```

### Step 3 – PF Actions (Clearance vs OFP + Navigation System Entry/Verification)

| Role | Action |
|------|--------|
| **PF** | Check received clearance versus the (NAVLOG) OFP. |
| **PF** | Thereafter enter and/or verify the route in the navigation system as follows: |

1. **Verify the waypoint Latitude and Longitude.**  
   Waypoints which are displayed in coded form (e.g. **4550N**) shall be verified using the **full Latitude and Longitude** of the coded waypoint.
2. Verify waypoints sequence and, if applicable, given number.
3. Verify distance between waypoints.

```
          ┌─────────────────────────────────────┐
          │  PF: Clearance vs (NAVLOG) OFP      │
          │  Enter / verify route in Nav System │
          │                                     │
          │  (i)  Full Lat/Long (incl. coded)   │
          │  (ii) Sequence & number             │
          │  (iii) Distance between waypoints   │
          └──────────────────┬──────────────────┘
                             │
                             ▼
```

### Step 4 – PM Verification (Nav System → OFP)

| Role | Action |
|------|--------|
| **PM** | Verify the route inserted in the navigation system, working **from the navigation system to the OFP**. |
| **PM** | Verify waypoint sequence and, if applicable, given number. |

```
          ┌─────────────────────────────────────┐
          │  PM: Verify from Nav System → OFP   │
          │  Check waypoint sequence & number   │
          └──────────────────┬──────────────────┘
                             │
                             ▼
```

### Step 5 – Flight Note

| Role | Action |
|------|--------|
| **Crew** | Report in **FLIGHT NOTE** that the check in (1) has been performed. |

```
          ┌─────────────────────────────────────┐
          │  Report in FLIGHT NOTE that         │
          │  check in (1) has been performed    │
          └──────────────────┬──────────────────┘
                             │
                             ▼
```

## (b) In MNPS airspace

### When passing waypoints – perform the following checks

| # | Check |
|---|-------|
| **(i)** | Just prior to the waypoint, check the **present position coordinates** of each navigation system against the cleared route in the OFP. |
| **(ii)** | Check the **next two waypoints** in each navigation system against the OFP. |
| **(iii)** | At the waypoint: check the distance to the next waypoint, confirm that the aircraft turns in the **correct direction** and takes up a new heading and track appropriate to the leg to the next waypoint. |
| **(iv)** | Before transmitting the position report to ATC, verify the waypoint co-ordinates against the OFP and those in the steering navigation system. When feasible the position report **“next”** and **“next plus 1”** waypoint co-ordinates should be read from the CDU of the navigation system coupled to the autopilot. |

```
          ┌──────────────────────────────────────────────────┐
          │              PASSING WAYPOINTS                   │
          │                                                  │
          │  (i)  Present position vs OFP (just prior)       │
          │  (ii) Next two WPTs in each Nav System vs OFP    │
          │  (iii) Distance + correct turn + new hdg/track   │
          │  (iv) Verify WPT coords before position report   │
          │       (read “next” + “next+1” from CDU if feasible)│
          └──────────────────────┬───────────────────────────┘
                                 │
                                 ▼
```

### On Reclearance

When a **reclearance** of the flight plan route is received by **voice or by ACARS**:

→ Perform the full procedure described in **(a)(1) to (a)(4)** above.

```
          ┌─────────────────────────────────────┐
          │  Reclearance received               │
          │  (Voice or ACARS)                   │
          └──────────────────┬──────────────────┘
                             │
                             ▼
          ┌─────────────────────────────────────┐
          │  RETURN TO (a) Steps 1 → 4          │
          │  (Full independent verification)    │
          └─────────────────────────────────────┘
```

## Summary Flow (High Level)

```
Receive Clearance / Re-route
         │
         ▼
┌────────────────────────────┐
│ (a) Pre-Entry Verification │
│ 1. Dual listen + record    │
│ 2. PM: Note + route check  │
│ 3. PF: Enter/verify in FMC │
│ 4. PM: Cross-check FMC→OFP │
│ 5. Flight Note             │
└────────────┬───────────────┘
             │
             ▼
      Enter MNPS Airspace
             │
             ▼
┌────────────────────────────┐
│ (b) Passing Waypoints      │
│ • Present pos check        │
│ • Next 2 WPTs check        │
│ • Turn / distance / track  │
│ • Position report verify   │
└────────────┬───────────────┘
             │
     Reclearance? ──Yes──► Return to (a) 1-4
             │
            No
             │
             ▼
      Continue MNPS
```

---

**Notes**
- All steps in (a) must be performed **independently** and **in sequence**.
- Coded waypoints (e.g. 4550N) **must** be expanded to full Latitude/Longitude.
- Dual verification (PF ↔ PM) is mandatory and cannot be delegated.
- On any reclearance (voice or ACARS) the full pre-entry procedure (a)(1)–(a)(4) is re-applied.
